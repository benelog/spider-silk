= Installation
:navtitle: Installation

Spider Silk requires Java 21 or later.
Releases are published to https://github.com/benelog/spider-silk/packages[GitHub Packages], not to Maven Central.
The current version is `{project-version}`.

[IMPORTANT]
====
GitHub Packages requires authentication even for public repositories.
Create a https://github.com/settings/tokens[personal access token (classic)] with the `read:packages` scope and use it as the password.
====

== Gradle

[source,groovy,subs="attributes+"]
----
repositories {
    mavenCentral()
    maven {
        url = uri('https://maven.pkg.github.com/{project-repo}')
        credentials {
            username = System.getenv('GITHUB_ACTOR')
            password = System.getenv('GITHUB_TOKEN')   // a PAT with read:packages
        }
    }
}

dependencies {
    implementation '{project-group}:spider-silk-core:{project-version}'
    testImplementation '{project-group}:spider-silk-test:{project-version}'
}
----

Keep the credentials out of the build file.
Put them in `~/.gradle/gradle.properties` and read them with `findProperty`:

[source,properties]
----
gpr.user=your-github-username
gpr.token=ghp_yourPersonalAccessToken
----

[source,groovy]
----
credentials {
    username = project.findProperty('gpr.user') ?: System.getenv('GITHUB_ACTOR')
    password = project.findProperty('gpr.token') ?: System.getenv('GITHUB_TOKEN')
}
----

== Maven

Declare the repository in `pom.xml`:

[source,xml,subs="attributes+"]
----
<repositories>
  <repository>
    <id>github</id>
    <url>https://maven.pkg.github.com/{project-repo}</url>
    <snapshots>
      <enabled>true</enabled>
    </snapshots>
  </repository>
</repositories>

<dependencies>
  <dependency>
    <groupId>{project-group}</groupId>
    <artifactId>spider-silk-core</artifactId>
    <version>{project-version}</version>
  </dependency>
  <dependency>
    <groupId>{project-group}</groupId>
    <artifactId>spider-silk-test</artifactId>
    <version>{project-version}</version>
    <scope>test</scope>
  </dependency>
</dependencies>
----

A build that also inherits the packaging conventions from xref:maven-parent.adoc[the Maven parent] must declare this repository in `~/.m2/settings.xml` instead.
Maven resolves a `<parent>` before it reads the pom's `<repositories>`.
The credentials go in `~/.m2/settings.xml` either way, under the same `id`:

[source,xml]
----
<settings>
  <servers>
    <server>
      <id>github</id>
      <username>your-github-username</username>
      <password>ghp_yourPersonalAccessToken</password>
    </server>
  </servers>
</settings>
----

== Hello, world

[source,java]
----
import net.benelog.spidersilk.App;
import net.benelog.spidersilk.WebResponse;

public class Main {

    public static void main(String[] args) {
        App app = new App();
        app.get("/hello/{name}", req -> WebResponse.text("Hello, " + req.pathParam("name")));
        app.start(8080);
    }
}
----

[source,bash]
----
$ curl localhost:8080/hello/silk
Hello, silk
----

`spider-silk-core` brings embedded Jetty with it, so nothing else is needed to serve a request.
Add `spider-silk-tomcat` or `spider-silk-undertow` to run the same app on an embedded Tomcat or Undertow; see xref:server.adoc#choosing[Choosing a server].
See xref:deployment.adoc[Deployment] to deploy on an external servlet container instead.
Templates render with jte out of the box.
xref:freemarker.adoc[FreeMarker], xref:handlebars.adoc[Handlebars], and xref:thymeleaf.adoc[Thymeleaf] are modules of their own, added the same way.
xref:websocket.adoc[`spider-silk-jetty-websocket`] adds WebSocket endpoints, and works on Jetty only.
xref:openapi.adoc[`spider-silk-openapi`] turns the route list into an OpenAPI document.

[#names]
== Coordinates, packages, and module names

`{project-group}` is one string, used three ways on purpose.

[cols="1,3",options="header"]
|===
| Where | What it is

| Group id
| `{project-group}`, with the module's own name as the artifact id — `{project-group}:spider-silk-core`

| Package root
| `{project-group}`, with core owning it and each other module a subpackage — `{project-group}.tomcat`, `{project-group}.jetty.websocket`

| `Automatic-Module-Name`
| The package root the jar carries, so `import` and the module path spell the same name — `{project-group}`, `{project-group}.tomcat`, `{project-group}.jetty.websocket`
|===

The xref:gradle-plugin.adoc[Gradle plugin] is applied by that same id, `{project-group}`, and the xref:maven-parent.adoc[Maven parent] is `{project-group}:spider-silk-maven-parent`.
https://github.com/benelog/spider-silk/blob/main/notes/decisions.md[Decision 32] gives the reasoning.
