= Installation
:navtitle: Installation

Spider Silk requires Java 21 or later.
Releases are published to https://central.sonatype.com/namespace/net.benelog[Maven Central], so a build needs no repository beyond the default one.
The current version is `{project-version}`.
https://github.com/{project-repo}/blob/main/CHANGELOG.md[CHANGELOG.md] lists what changed in each release.

== Gradle

[source,groovy,subs="attributes+"]
----
repositories {
    mavenCentral()
}

dependencies {
    implementation '{project-group}:spider-silk-core:{project-version}'
    testImplementation '{project-group}:spider-silk-test:{project-version}'
}
----

== Maven

Maven resolves from Central by default, so `pom.xml` declares the dependencies and nothing else:

[source,xml,subs="attributes+"]
----
<dependencies>
  <dependency>
    <groupId>{project-group}</groupId>
    <artifactId>spider-silk-core</artifactId>
    <version>{project-version}</version>
  </dependency>
  <dependency>
    <groupId>{project-group}</groupId>
    <artifactId>spider-silk-test</artifactId>
    <version>{project-version}</version>
    <scope>test</scope>
  </dependency>
</dependencies>
----

== Hello, world

[source,java]
----
import net.benelog.spidersilk.App;
import net.benelog.spidersilk.WebResponse;

public class Main {

    public static void main(String[] args) {
        App app = new App();
        app.get("/hello/{name}", req -> WebResponse.text("Hello, " + req.pathParam("name")));
        app.start(8080);
    }
}
----

[source,bash]
----
$ curl localhost:8080/hello/silk
Hello, silk
----

`spider-silk-core` brings embedded Jetty with it, so nothing else is needed to serve a request.
See xref:deployment.adoc[Deployment] to deploy on an external servlet container instead.

[#modules]
== Modules

The modules fall into four groups.
Only the core group is needed, and the others are added one at a time, the same way as core.

=== Core

Every application uses these two.

[cols="2,3",options="header"]
|===
| Module | Contents

| `spider-silk-core`
| The framework, with jte templates and embedded Jetty

| `spider-silk-test`
| xref:testing.adoc[`WebTest` and `TestRequest`], for test scope
|===

=== Extensions

An extension is optional.
Add one only when you want what it names instead of, or beside, the core default.

[cols="2,3",options="header"]
|===
| Module | Use it when you want

2+h| Servers: core's default is Jetty, and xref:server.adoc#choosing[Choosing a server] covers the choice

| `spider-silk-tomcat`
| xref:tomcat.adoc[`TomcatServer`]: an embedded Tomcat

| `spider-silk-undertow`
| xref:undertow.adoc[`UndertowServer`]: an embedded Undertow

2+h| Templates: core's default is jte

| `spider-silk-freemarker`
| xref:freemarker.adoc[`FreeMarkerTemplates`]: FreeMarker

| `spider-silk-handlebars`
| xref:handlebars.adoc[`HandlebarsTemplates`]: Handlebars

| `spider-silk-thymeleaf`
| xref:thymeleaf.adoc[`ThymeleafTemplates`]: Thymeleaf

2+h| Features

| `spider-silk-jetty-websocket`
| xref:websocket.adoc[`WebSockets`]: WebSocket endpoints beside the routes, on Jetty only

| `spider-silk-openapi`
| xref:openapi.adoc[`OpenApi`]: the route list as an OpenAPI 3.1 document
|===

=== Build

The build modules carry optional packaging conventions: precompiled jte, a Jib image, and a native build.

[cols="2,3",options="header"]
|===
| Module | Build tool

| `spider-silk-gradle-plugin`
| xref:gradle-plugin.adoc[Gradle], applied as the plugin `{project-group}`

| `spider-silk-maven-parent`
| xref:maven-parent.adoc[Maven], used as the parent POM
|===

[#names]
== Coordinates, packages, and module names

`{project-group}` is one string, used three ways on purpose.

[cols="1,3",options="header"]
|===
| Where | What it is

| Group id
| `{project-group}`, with the module's own name as the artifact id — `{project-group}:spider-silk-core`

| Package root
| `{project-group}`, with core owning it and each other module a subpackage — `{project-group}.tomcat`, `{project-group}.jetty.websocket`

| `Automatic-Module-Name`
| The package root the jar carries, so `import` and the module path spell the same name — `{project-group}`, `{project-group}.tomcat`, `{project-group}.jetty.websocket`
|===

The xref:gradle-plugin.adoc[Gradle plugin] is applied by that same id, `{project-group}`, and the xref:maven-parent.adoc[Maven parent] is `{project-group}:spider-silk-maven-parent`.
https://github.com/benelog/spider-silk/blob/main/notes/decisions.md[Decision 32] gives the reasoning.
