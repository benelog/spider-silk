= The Request
:navtitle: The Request

`WebRequest` is the handler's view of what the client sent.
The sections below cover the parts that need more than a getter: cookies, repeated parameters, the query-string and form-body split, and content negotiation.

== Cookies

The request reads the cookies the client sent, and the response sets the ones the server sends.
Cookies split along the same line as the rest of the API.

[source,java]
----
String theme = req.cookie("theme");         // null when absent
Map<String, String> all = req.cookies();    // a repeated name keeps the first value
----

`WebResponse.cookie(...)` sets one, with the defaults xref:response.adoc#cookies[The Response] describes.

== Repeated parameters

`params(name)` reads every value a repeated parameter carries.

[source,java]
----
List<String> tags = req.params("tag");      // ?tag=java&tag=web, or a checkbox group
----

The values come back in request order, and an absent parameter gives an empty list: "no boxes checked" is an answer, not a 400.
`param(name)` still returns the first value and still answers 400 when there is none.
`paramLong("page", 1)` and `paramEnum("direction", Direction.class, Direction.FRONT)` supply a default for an optional typed parameter.
The default covers absence only.
A parameter that is present but unparseable is still a 400.

== Query string vs. form body

The servlet API merges the two, so `param("id")` answers an `id` in the URL and an `id` in the form alike.
Name the source when the difference matters:

[source,java]
----
String page = req.queryParam("page");     // query string only, null when absent
String name = req.formParam("name");      // form body only
List<String> tags = req.formParams("tag");
----

== Content negotiation

`accepts` reads the `Accept` header and reports which of the media types a handler offers the caller wants:

[source,java]
----
app.get("/decks", req -> switch (req.accepts("text/html", "application/json")) {
    case "application/json" -> WebResponse.json(deckService.decks(), Codecs::writeDecks);
    default -> WebResponse.template("decks", Map.of("decks", deckService.decks()));
});
----

The answer is one of the strings passed in, so it reads back as a `case` label and no media type is spelled twice.
Quality values and specificity are applied the way the specification asks: `text/html` is matched before `text/*`, which is matched before a bare wildcard, and a type the caller weighted `q=0` is one it refused even when a wildcard would otherwise have covered it.

Two edges are worth stating, because they are the ones every hand-written parser gets wrong:

* A request with no `Accept` at all is a caller that never said, not one that will take nothing — the first candidate wins, so the list is written in the order the handler prefers.
* A caller that will take none of them is answered `406 Not Acceptable`, the same way `param(name)` answers 400 rather than returning null.

A handler therefore never has a null branch to write.

Asking the question makes the answer depend on a request header, so the response carries `Vary: Accept` without the handler saying so — including the 406, and including an answer that turned out to be the only type on offer.
That is the same bookkeeping `app.gzip()` does for `Accept-Encoding`, for the same reason: a shared cache must not hand JSON to the next browser.

For the rare decision `accepts` cannot phrase, `req.acceptedTypes()` is the parsed view behind it — the media types asked for, best first, the refused ones dropped, and empty when the request sent no `Accept`.

`Accept-Language` and `Accept-Encoding` are not negotiated for you.
Encoding is the compression layer's own business, and language would be a locale story core does not have.

== File uploads

`req.file(name)` reads a file out of a multipart form, answering 400 when the part is missing and 400 when the request is not multipart at all:

[source,java]
----
app.post("/decks/{deckId}/import", req -> {
    UploadedFile file = req.file("file");
    int imported = deckService.importCsv(req.pathParamLong("deckId"), file.asText());
    req.flash("message", "Imported " + imported + " cards.");
    return WebResponse.redirect("/decks/" + req.pathParam("deckId"), HttpStatus.SEE_OTHER);
});
----

`UploadedFile` answers `fileName()`, `contentType()`, `size()`, and the content as `bytes()` or as UTF-8 text with `asText()`.
The limits — maximum sizes, and where a large upload is buffered — are the servlet container's multipart configuration, set on the server: `multipart(new MultipartConfigElement(...))` on `JettyServer`, xref:tomcat.adoc[TomcatServer], and xref:undertow.adoc[UndertowServer] alike.
The default buffers to the system temp directory with no size cap and a 1MB in-memory threshold; `multipart(null)` turns multipart handling off.
