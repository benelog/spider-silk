= Filters and Errors
:navtitle: Filters and Errors

A filter runs before or after a route handler.
An exception handler turns an exception a handler threw into a response.
An error handler fills in the body of a response that ended on a status with nothing to show.

== Filters

`before` and `after` take an optional path, and cover everything in scope when given none.
A trailing `*` covers the prefix _and_ everything under it, so `/admin/*` guards `/admin` as well as `/admin/users`, which is what a guard almost always means:

[source,java]
----
app.before("/admin/*", req -> req.sessionAttr("user") == null
        ? WebResponse.redirect("/login")    // answers here, so the route handler never runs
        : null);                            // carry on
----

A before-filter that returns a response ends the request there.
Returning `null` continues to the route.
Throw `new HttpException(HttpStatus.UNAUTHORIZED, "...")` to reject without a body of your own, and let `error(HttpStatus.UNAUTHORIZED, ...)` render it.

An after-filter takes the response the route returned and hands back a replacement, or `null` to leave it alone:

[source,java]
----
app.after((req, res) -> res.header("X-Request-Id", requestId()));
----

== Exception handlers

`exception(Type, handler)` answers a request whose handler threw an exception of that type or a subtype:

[source,java]
----
app.exception(IllegalArgumentException.class,
        (e, req) -> WebResponse.text(e.getMessage()).status(HttpStatus.NOT_FOUND));
app.exception(Json.JsonException.class,
        (e, req) -> WebResponse.text(e.getMessage()).status(HttpStatus.BAD_REQUEST));
----

The handler for the most specific type the exception is an instance of runs, whatever order the handlers were registered in.
`Json.JsonException` is an `IllegalArgumentException`, and a body that failed to parse reaches the second handler above rather than the first.
Registering a type twice replaces the first handler.
An `HttpException` no handler covers answers with its status and message, and any other uncovered exception answers 500 and is logged.
A template that fails to render throws inside the handler's own dispatch, so it reaches these handlers too.

== Error handlers

`error(status, handler)` fills in the body for any response that ended on that status with no body, whether from the router, from an `HttpException`, or from a handler that returned `WebResponse.empty(HttpStatus.FORBIDDEN)`.
`error(HttpStatus.NOT_FOUND, handler)` therefore styles the router's own 404 and every handler-made one alike, in one registration.
A response that already carries a body is left alone.
What the error handler returns keeps the headers the framework had already worked out, such as the `Allow` of a 405.
It answers with the registered status unless it sets one of its own.
Inside an error handler, `req.errorMessage()` is the plain-text message the framework would have used.

Both lists are readable back.
`app.guards()` reports the filters and the error handlers the way `app.routes()` reports the routes, in xref:route-introspection.adoc#guards[Route Introspection].
