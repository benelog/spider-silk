= OpenAPI Export
:navtitle: OpenAPI Export

`spider-silk-openapi` turns xref:route-introspection.adoc[`app.routes()`] into an OpenAPI 3.1 document.
It is a reader over that list and nothing else.
Core hands the routes out as plain data and needs no change for this module: `PathPattern`'s `\{deckId}` already _is_ OpenAPI's path template, so there is nothing to translate and nothing to reflect over.

The export is a module rather than a method on `App` for a second reason.
A spec format is not the web tier, and a version this framework does not own should not be pinned inside the one artifact every application depends on.
The same reasoning keeps the `WebTest` harness in xref:testing.adoc[`spider-silk-test`].

== Installation

[source,groovy,subs="attributes+"]
----
dependencies {
    implementation '{project-group}:spider-silk-openapi:{project-version}'
}
----

The module adds no dependency beyond core: it is one class over core's route list and core's `Json`.

== Serving the document

[source,java]
----
app.get("/openapi.json", req -> {
    Json.JsonValue resBody = OpenApi.document("Flashcard API", "1.0.0", app.routes());
    return WebResponse.json(resBody);
});
----

The title and version are arguments because OpenAPI requires both under `info`, and a default for either would be this module naming someone's API.
`document` returns a `Json.JsonValue`, so it composes with everything else in xref:json.adoc[the JSON API].
Writing it to a file at build time is the same call.

The handler reads `app.routes()` per request, so it lists whatever was registered, including routes added after this line.

== Which routes go in

Every route in the list goes in, unless you narrow the list first.
An application that serves HTML alongside its API passes the API's routes and not everything:

[source,java]
----
List<Route> documented = app.routes().stream()
        .filter(route -> route.path().startsWith("/api"))
        .toList();
----

That selection stays the application's, which is the reason `routes()` hands back a list in the first place.
This module has no way to tell an HTML page from an endpoint, and a default built on a guess would always be wrong for some application.

A route whose pattern contains a bare `*` throws `IllegalArgumentException`.
That wildcard has no OpenAPI path template and no name to put in one.
Dropping the route quietly would publish a document claiming the application answers less than it does.
The export refuses it instead, and leaving such a route out is a filter you write, visibly, next to the one above.

A xref:routing.adoc[named tail] is written out rather than refused.
`/files/\{path*}` becomes the path `/files/\{path}`, and its parameter carries the description `The rest of the path, slashes included.`
OpenAPI has no wildcard in a path template, so the star stays behind as core's syntax and only the variable crosses over.
Dropping the star is the only translation this module does.

== What the document contains

Every route becomes an operation under its path, keyed by the lowercased method, in registration order.
Every `\{name}` in a path becomes a required path parameter of type `string`, which OpenAPI insists on declaring.
Each operation carries a `200` response described as `OK`.

A route registered with a xref:route-introspection.adoc#descriptions[description] carries it as the operation's `summary`, which is the field a spec UI shows beside the route:

[source,java]
----
app.get("/api/decks", "List every deck", api::listDecks);
----

[source,json]
----
{"paths": {"/api/decks": {"get": {"summary": "List every deck", "responses": {"200": {"description": "OK"}}}}}}
----

A route registered without one gets no `summary` at all, rather than an empty string that would render as a blank line.

The document contains nothing more, and it is still a valid OpenAPI document.
What is missing is missing on purpose: a request or response schema, a server list, and a security scheme.
None of those is derivable from a route, so each would have to be declared somewhere.
This module sidesteps the question of where by declaring none of them.
The automatic HEAD and OPTIONS answers are not listed either, for the reason `routes()` does not list them.

== Testing it

`document` is a pure function of a list, so a test needs no server and no app:

[source,java]
----
Json.JsonObject paths = OpenApi.document("Flashcard API", "1.0.0",
        List.of(new Route("GET", "/api/decks/{deckId}/cards"))).asObject().getObject("paths");

assertThat(paths.getObject("/api/decks/{deckId}/cards").getObject("get").getArray("parameters"))
        .hasSize(1);
----

`Route` is a record, so a fixture is a constructor call.
The example app's document is reachable at `/openapi.json`.
A spec document is the one resource there meant to be read by something other than the application, so xref:example-flashcard.adoc[the example] scopes its CORS to that path alone.
