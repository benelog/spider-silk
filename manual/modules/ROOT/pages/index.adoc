= Spider Silk
:navtitle: Introduction

image::logo.svg[Spider Silk,160]

Thin by design, strong by types.

Spider Silk is a web framework built on the Jakarta Servlet API.

== Three core principles

No reflection.::
There is no annotation scanning, no proxies, and no automatic binding.
What runs is what the code says, stack traces stay short, and startup stays fast.

The API is intuitively simple.::
A handler is a function from a request to a response: `WebResponse handle(WebRequest request)`.
That signature is the whole model.

Better RESTful API support than raw servlets.::
Routing is per method, paths carry variables, parameters are extracted with a declared type, and exceptions map to status codes.

The default template engine is https://jte.gg[jte].
jte compiles templates to Java source, which matches how the rest of the framework works.

== At a glance

[source,java]
----
App app = new App();    // jte over classpath:/jte, and classpath:/public served at /

app.get("/decks/{deckId}", req -> {
    long deckId = req.pathParamLong("deckId");  // non-numeric input becomes a 400
    return WebResponse.template("deck", model); // classpath:/jte/deck.jte
});

app.get("/api/decks", req -> WebResponse.json(
        Json.arr().add(Json.obj().put("id", 1L).put("name", "English"))));

app.post("/api/decks", req -> {
    String name = req.bodyJson().asObject().getString("name");
    return WebResponse.json(Json.obj().put("name", name)).status(HttpStatus.CREATED);
});

app.path("/api/decks", group -> {
    group.before(req -> requireApiKey(req));    // covers /api/decks and everything under it
    group.get("", api::listDecks);              // GET  /api/decks
    group.get("/{deckId}", api::showDeck);      // GET  /api/decks/{deckId}
});

app.exception(IllegalArgumentException.class,
        (req, e) -> WebResponse.text(e.getMessage()).status(HttpStatus.NOT_FOUND));
app.exception(Json.JsonException.class,        // the more specific type wins, whatever the order
        (req, e) -> WebResponse.text(e.getMessage()).status(HttpStatus.BAD_REQUEST));

app.error(HttpStatus.NOT_FOUND, req -> WebResponse.template("not-found", Map.of("path", req.path())));

app.start(8080);                                // embedded Jetty, sessions on
----

`start` returns as soon as the port is bound.
Everything is registered before it: a route, a filter, or a setting added to a running application throws `IllegalStateException`.
The server's threads keep the JVM alive from there, so `join()` is only needed when you want to block the main thread as well.
`stop()` shuts the server down.
`port()` reports the bound port, which is how a test reads back the port the OS picked for `start(0)`.

== Positioning and roadmap

https://github.com/benelog/spider-silk/blob/main/notes/positioning.md[notes/positioning.md] places Spider Silk next to Javalin, Spark, Helidon SE, and Spring Boot, and states what it trades away to get there.

https://github.com/benelog/spider-silk/blob/main/notes/decisions.md[notes/decisions.md] gives the reasoning behind each piece, item by item, together with the list of what was rejected.

https://github.com/benelog/spider-silk/issues[The issue tracker] records what was deliberately deferred, one issue per item, with the condition that would make it worth doing.
