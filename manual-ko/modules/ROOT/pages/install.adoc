= 설치
:navtitle: 설치

Spider Silk는 Java 21 이상이 필요하다.
릴리스는 https://central.sonatype.com/namespace/net.benelog[Maven Central]에 게시되므로, 빌드에 기본 저장소 말고 다른 저장소를 추가할 필요가 없다.
현재 버전은 `{project-version}`이다.
https://github.com/{project-repo}/blob/main/CHANGELOG.md[CHANGELOG.md]에 릴리스마다 바뀐 내용이 정리되어 있다.

== Gradle

[source,groovy,subs="attributes+"]
----
repositories {
    mavenCentral()
}

dependencies {
    implementation '{project-group}:spider-silk-core:{project-version}'
    testImplementation '{project-group}:spider-silk-test:{project-version}'
}
----

== Maven

Maven은 기본적으로 Central에서 의존성을 받아 오므로, `pom.xml`에는 의존성 선언만 있으면 된다:

[source,xml,subs="attributes+"]
----
<dependencies>
  <dependency>
    <groupId>{project-group}</groupId>
    <artifactId>spider-silk-core</artifactId>
    <version>{project-version}</version>
  </dependency>
  <dependency>
    <groupId>{project-group}</groupId>
    <artifactId>spider-silk-test</artifactId>
    <version>{project-version}</version>
    <scope>test</scope>
  </dependency>
</dependencies>
----

== Hello, world

[source,java]
----
import net.benelog.spidersilk.App;
import net.benelog.spidersilk.WebResponse;

public class Main {

    public static void main(String[] args) {
        App app = new App();
        app.get("/hello/{name}", req -> WebResponse.text("Hello, " + req.pathParam("name")));
        app.start(8080);
    }
}
----

[source,bash]
----
$ curl localhost:8080/hello/silk
Hello, silk
----

`spider-silk-core`는 내장 Jetty를 함께 가져오므로, 요청을 처리하는 데 더 추가할 것이 없다.
대신 외부 서블릿 컨테이너에 배포하려면 xref:deployment.adoc[배포]를 참고한다.

== 모듈

모듈은 네 묶음으로 나뉜다.
필요한 것은 코어 묶음뿐이며, 나머지는 코어와 같은 방식으로 하나씩 추가한다.

=== 코어

모든 애플리케이션이 이 둘을 쓴다.

[cols="2,3",options="header"]
|===
| 모듈 | 내용

| `spider-silk-core`
| jte 템플릿과 내장 Jetty를 포함한 프레임워크

| `spider-silk-test`
| 테스트 범위의 xref:testing.adoc[`WebTest`와 `TestRequest`]
|===

확장은 선택 사항이다.
그 모듈이 가리키는 것을 코어 기본값 대신, 또는 그 곁에 쓰고 싶을 때만 추가한다.

[cols="2,3",options="header"]
|===
| 모듈 | 이럴 때 쓴다

2+h| 서버: 코어 기본값은 Jetty이며, 고르는 기준은 xref:server.adoc#choosing[서버 고르기]에서 다룬다

| `spider-silk-tomcat`
| xref:tomcat.adoc[`TomcatServer`]: 내장 Tomcat

| `spider-silk-undertow`
| xref:undertow.adoc[`UndertowServer`]: 내장 Undertow

2+h| 템플릿: 코어 기본값은 jte다

| `spider-silk-freemarker`
| xref:freemarker.adoc[`FreeMarkerTemplates`]: FreeMarker

| `spider-silk-handlebars`
| xref:handlebars.adoc[`HandlebarsTemplates`]: Handlebars

| `spider-silk-thymeleaf`
| xref:thymeleaf.adoc[`ThymeleafTemplates`]: Thymeleaf

2+h| 기능

| `spider-silk-jetty-websocket`
| xref:websocket.adoc[`WebSockets`]: 라우트 곁의 WebSocket 엔드포인트, Jetty 전용

=== 빌드

빌드 모듈은 선택적인 패키징 관례를 담는다: 미리 컴파일한 jte, Jib 이미지, 네이티브 빌드.

[cols="2,3",options="header"]
|===
| 모듈 | 빌드 도구

| `spider-silk-gradle-plugin`

| `spider-silk-maven-parent`
| xref:maven-parent.adoc[Maven], 부모 POM으로 쓴다
|===

== 좌표, 패키지, 모듈 이름

`{project-group}`이라는 한 문자열이 의도적으로 세 가지 용도로 쓰인다.

[cols="1,3",options="header"]
|===
| 어디에 | 무엇인가

| 그룹 id
| `{project-group}`, 아티팩트 id는 모듈 자체의 이름 — `{project-group}:spider-silk-core`

| 패키지 루트
| `{project-group}`, 코어가 이를 소유하고 다른 모듈은 각각 하위 패키지 — `{project-group}.tomcat`, `{project-group}.jetty.websocket`

| `Automatic-Module-Name`
| jar가 담는 패키지 루트로, `import`와 모듈 경로가 같은 이름을 쓴다 — `{project-group}`, `{project-group}.tomcat`, `{project-group}.jetty.websocket`
|===

xref:gradle-plugin.adoc[Gradle 플러그인]은 같은 id인 `{project-group}`으로 적용되고, xref:maven-parent.adoc[Maven 부모 POM]은 `{project-group}:spider-silk-maven-parent`다.
https://github.com/benelog/spider-silk/blob/main/notes/decisions.md[결정 32]가 그 근거를 제시한다.
